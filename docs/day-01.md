# Day 1 · 数据底座:外链列表入库与初筛

> 模型未选定,今天不调 AI,先把后面所有 AI 环节要用的数据底座打好。

## 今天做了什么

- Spring Boot 4 + MyBatis + Flyway 骨架,分层 MVC(controller/service/mapper/entity/dto),连接 Neon `dev` 分支。
- `DataSourceConfig`:把 Neon 的 `postgresql://user:pass@host/db` 转成 JDBC;开发期去掉 `-pooler` 直连。
- `V1__init.sql`:启用 pgvector,建 6 张表(见 `design.md`)。
- 外链列表导入:Markdown 表格 / 每行一个 URL → 规范化 → 列表内去重 → 库内去重。
- 结果:743 条入口,列表内重复 44 条,入库 699 条唯一入口。

## 踩坑与取舍

1. **解析范围过宽**:最初把说明文字里的链接也当入口,误入 3 条。改为表格只收"首列是编号"的行,纯 URL 模式要求整行就是 URL。
2. **远程库逐条插入太慢**:699 条用了 4 分 41 秒(每条一次往返)。改为 MyBatis `<foreach>` 多值插入,每 200 条一批,降到约 1.6 秒;`on conflict do nothing` 的影响行数就是实际插入数。
3. **去重粒度**:按规范化后的完整 URL 去重,而不是按域名。同一域名可能有多个不同的提交入口(本次有 56 条)。
4. **初筛不用模型**:入库阶段只做便宜、确定性的处理;模型研判留到"为某个站选用一批候选"时再做,控制成本。

## 面试可以怎么讲

- 为什么连接池 / 直连要区分?(PgBouncer 事务模式下会话级 advisory lock 不可靠,Flyway 迁移需要会话锁)
- 导入如何做到幂等?(规范化键 + 唯一约束 + `on conflict do nothing`,可重复导入)
- 远程数据库批量写入怎么优化?(减少往返:批处理、多值插入;衡量指标是往返次数而不是 SQL 条数)
